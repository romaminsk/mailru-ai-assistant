# Демонстрация: платежи и чеки из почты

## Задача

Собрать платежи и чеки из PNG/PDF-вложений Mail.ru за 16.07.2026–16.10.2026 и показать: сколько потрачено, кому, за что. Каждую цифру можно проверить по оригиналу.

## Роль AI

Путь обработки:

1. OCR (Tesseract, локально) и текст из PDF.
2. Облачная модель (схема v3) извлекает получателя, сумму, валюту, дату, назначение, описание, комиссию и отток.
3. Локальная проверка: цитаты в тексте, валюта, сумма, дата; сомнительное уходит на проверку.
4. SQLite: результаты, версии, история правок.
5. Отчёт и главный экран.

Локальные LLM не используются. Почта только для чтения.

## Запуск на рабочей базе

```bash
cd /Users/roma/ai-stuff/mailru-ai-assistant
.venv/bin/python -m streamlit run mail_assistant/web.py --server.address 127.0.0.1 --server.port 8501
```

Открыть: http://127.0.0.1:8501. База: `data/receipts.sqlite3` (в Git не попадает).

## Порядок показа

1. Главный экран: период и «Потрачено» по валютам.
2. «Кому отправлены деньги» и «Все платежи» (дата, кому, сумма, за что).
3. Вкладка «Проверить записи»: выбрать платёж, открыть оригинал (PNG/PDF).
4. Показать строку комиссии (если есть) и то, что отток не удваивается.
5. Исправить назначение в поле «За что / назначение платежа», сохранить.
6. Подтвердить запись.
7. Перезапустить сервер и открыть страницу: данные на месте.

## Ограничения

- Назначение не заполнено у 28 записей; в таблице показано «—».
- У части ЖКХ-платежей через ЕРИП получатель — посредник «НКФО ЕРИП».
- 5 документов не распознаны из-за обрезки ответа модели; 1 документ — дубль PDF той же операции.
- Записи без даты не входят в сумму периода.
- Лимит облака на этап — 100 запросов; все они израсходованы (фактически 101 с проверкой на шаге 0).
- Сверено по оригиналам 8 из 20 документов; приёмка 18/20 не подтверждена.
- E2E-тесты в Playwright нестабильны из-за перерисовки Streamlit; юнит-тесты проходят.
