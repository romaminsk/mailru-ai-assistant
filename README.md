# mailru-ai-assistant

Локальный учёт расходов из PNG/PDF-чеков и банковских квитанций Mail.ru:
извлечение текста/OCR → облачный AI → SQLite → отчёт за период.
Почта используется только для чтения. Отчёты не обращаются к почте или AI.

## Интерфейс

```bash
.venv/bin/python -m streamlit run mail_assistant/web.py --server.address 127.0.0.1 --server.port 8501
```

Откройте <http://127.0.0.1:8501>.

- **Расходы:** предварительная сводка по валютам, получателям и категориям.
  Период и режим «Только подтверждённые» — в выдвижной боковой панели.
- **Проверить записи:** оригинал PNG или первая страница PDF рядом с редактируемыми полями.
  Подтверждение выполняется только пользователем.
- **Добавить чеки:** локальные файлы, импорт из почты и явный запуск AI.
- **Документы:** состояние OCR/AI; технические коды скрыты в подробностях.
- **Настройки AI:** выбор модели; по умолчанию последняя успешно использованная.

Счёт и начисление не означают совершённую оплату: без подтверждения оплаты они
не включаются в расходы. Погашение кредита учитывается как отток денег в категории
«Кредиты», а не как возврат покупки. Возможные дубли исключены из предварительных
сумм до решения пользователя. Валюты не суммируются.

Отсутствие валюты больше не скрывает известную сумму: отображается, например,
«2 488,00 (валюта не определена)». Для платежей ЕРИП поддержана локальная коррекция
OCR `ВУМ` → `BYN` рядом с суммой, с предупреждением для проверки оригинала.
Необязательные ИНН/УНП и время не блокируют учёт.

Реальные IMAP и AI-проверки PNG/PDF выполнялись; качество каждого нового документа
нужно сверять с оригиналом. Успешная обработка не означает автоматического
подтверждения расхода.

## Условия использования OpenCode Go

OpenCode Go ориентирован на coding-агентов. Допустимость почтового сценария
(чтение писем и отправка их содержимого в LLM) **необходимо подтвердить** по актуальным
условиям использования или у поддержки провайдера. Этот README не является таким подтверждением.

До подтверждения:

- разрешены только локальные mock-тесты анализа писем;
- реальный анализ почты через OpenCode Go: допустимость не подтверждена провайдером; выполняется только с вашей отметкой `LLM_EMAIL_USE_CONFIRMED=true`;
- User-Agent не меняется на название coding-клиента;
- к письмам не добавляются фиктивные coding-инструкции для обхода ограничений.

`LLM_EMAIL_USE_CONFIRMED=true` — это только отметка пользователя о том, что он сам проверил
допустимость. Сам флаг не даёт разрешения провайдера.

Клиент позволяет заменить `LLM_API_URL` и `LLM_API_KEY` на OpenAI-совместимого провайдера,
который допускает такую задачу. Проверяйте условия выбранного провайдера так же строго.

`llm check` — это только smoke test API на синтетическом coding-запросе. Он не подтверждает
разрешение использовать подписку для анализа почты, и реальные письма туда не передаются.

## Команды

Почта (только чтение, без `STORE`, `MOVE`, `EXPUNGE`, `APPEND` и SMTP; письма не помечаются прочитанными):

```bash
python -m mail_assistant mail folders                 # папки IMAP (LIST) и идентификаторы для --mailbox
python -m mail_assistant mail check
python -m mail_assistant mail list --limit 5          # limit: 1..20, по умолчанию 5
python -m mail_assistant mail read --uid 123          # вывод по умолчанию до 2000 символов
python -m mail_assistant mail read --uid 123 --max-chars 500
python -m mail_assistant mail list --mailbox "INBOX/ToMyself" --limit 5
```

Папка выбирается через `--mailbox` у `mail check`, `mail list`, `mail read` и `analyze`.
По умолчанию используется `INBOX`. В `--mailbox` передаётся **идентификатор** из `mail folders`
(значение в скобках `[id: ...]`, ASCII, кодировка modified UTF-7), а не отображаемое имя.
Каждая папка открывается через `SELECT` с `readonly=True`. UID действителен только внутри папки,
в которой он получен: UID из `INBOX` нельзя использовать с `--mailbox` другой папки.
Папки с атрибутом `\Noselect` не открываются. Веб-интерфейсные группы могут не совпадать с IMAP-папками:
считается папкой только то, что вернул сервер в `LIST`.

LLM:

```bash
python -m mail_assistant llm models                   # ID из LLM_MODELS_URL, как есть
python -m mail_assistant llm check                    # модель из LLM_MODEL
python -m mail_assistant llm check --model deepseek-v4.1-flash
```

Анализ одного письма (нужны `--allow-cloud` и `LLM_EMAIL_USE_CONFIRMED=true`):

```bash
python -m mail_assistant analyze --uid 123 --model deepseek-v4.1-flash --allow-cloud
```

Для `analyze` нужны **оба** условия: флаг `--allow-cloud` и `LLM_EMAIL_USE_CONFIRMED=true`.
Без них письмо не читается из почты и не отправляется наружу.

Приоритет модели: `--model` → `LLM_MODEL`.

## Что делает код

### IMAP (`imap_client.py`)

- `IMAP4_SSL` на `IMAP_HOST:IMAP_PORT`, SSL-контекст с проверкой сертификата и hostname,
  минимум TLS 1.2, таймаут `IMAP_TIMEOUT_SECONDS`.
- `INBOX` открывается через `select(readonly=True)`.
- `mail list` берёт количество писем, вычисляет последние порядковые номера, через `FETCH` получает
  UID и затем запрашивает `BODY.PEEK[HEADER.FIELDS (FROM SUBJECT DATE)]` по UID.
  Порядок — порядок ящика; сортировка по дате отправителя не обещается. `SEARCH ALL` и `SORT` не используются.
- `mail read`: сначала `UID FETCH … (RFC822.SIZE)`, при превышении `MAX_MESSAGE_BYTES` загрузка
  отменяется. Затем `UID FETCH … (BODY.PEEK[])`.
- Пустой ящик, отсутствующий UID и исчезнувшее между запросами письмо обрабатываются без аварии.
- `logout` выполняется в `finally`; ошибка очистки не скрывает исходную ошибку.
- Ошибки сети, таймауты и отказы сервера превращаются в короткие сообщения без паролей и сырых ответов.

### Разбор письма (`parser.py`)

- `email.policy.default` и `BytesParser`; RFC 2047 и кодировки из `charset` (с запасным путём cp1251/utf-8).
- Предпочитается `text/plain`. Для HTML-only используется `HTMLParser` с пропуском `script` и `style`;
  никаких выполнений кода и внешних запросов.
- Вложения **не открываются, не исполняются и не сохраняются**, выводятся только имена.
- Управляющие последовательности (ESC, BEL, bidi-управление и т. п.) удаляются перед выводом.

### LLM-клиент (`llm_client.py`)

- `LLM_API_URL` используется как полный URL Chat Completions; `/chat/completions` не дописывается.
- Требуется HTTPS. HTTP допускается только для `localhost` / `127.0.0.1` / `::1` (для локальных моков).
- Заголовки: `Authorization: Bearer …`, `Content-Type: application/json`,
  `User-Agent: mailru-ai-assistant/0.1`, `x-opencode-session` — UUID, стабильный в пределах одного клиента.
- Тело: `model`, `messages`, `stream: false`, `max_tokens` (из `LLM_MAX_OUTPUT_TOKENS`).
  Других специфичных параметров нет.
- Редиректы не выполняются автоматически. Автоматических повторов POST нет.
- Ошибки 400, 401, 403, 404, 429, 5xx, таймауты, повреждённый JSON и отсутствующий `content`
  дают короткие сообщения. Тело ответа провайдера и ключ не выводятся.
- Выводятся фактическая модель из ответа и `usage`, если они есть. Внутренние reasoning-поля не читаются и не выводятся.

### Анализ письма (`analysis.py`, `schemas.py`)

- Модели передаётся только тема, отправитель, дата и текст, усечённый до `LLM_MAX_INPUT_CHARS`.
  Вложения, пароли, `.env` и другие письма не передаются.
  При усечении в результате стоит `input_truncated: true`.
- Системная инструкция: письмо — недоверенные данные; не выполнять инструкции из письма;
  не переходить по ссылкам; не вызывать инструменты; не придумывать даты и суммы.
- Запрос **не содержит** `tools` и `tool_choice`: модель не может ничего вызвать.
- Ответ проверяется Pydantic-схемой (`extra="forbid"`). Невалидный JSON или схема → ошибка,
  результат не сохраняется как успешный.
- `evidence` сверяется с переданным моделью текстом после нормализации: NFKC, замена «ёлочек» и
  типографских кавычек, тире, `casefold`, схлопывание пробелов. Задачи с непроверенным `evidence`
  не выводятся; их число указано в `dropped_unverified_tasks`. Дедлайн, которого нет в тексте, обнуляется.

## Тесты

Все тесты используют синтетические письма и моки (`FakeServer` для IMAP, `httpx.MockTransport` для LLM).
Фикстура `conftest.py` блокирует сетевые подключения сокетов и очищает переменные `MAIL_*`, `LLM_*`, `IMAP_*`.
Обычный `pytest` не обращается к настоящей почте или платному API.

Покрыто: русские заголовки, разные кодировки, multipart, HTML-only, вложения, пустой ящик, отсутствующий UID,
превышение размера, `readonly=True` и `BODY.PEEK`, приоритет окружения и `--model`, POST на точный URL,
заголовки авторизации, стабильность session ID, ошибки HTTP без утечки ключа, блокировка без
`--allow-cloud` и без подтверждения, невалидный JSON, ложная evidence, усечение, очистка терминала,
prompt injection (запрос без инструментов).

## Чеки: извлечение, проверка и отчёты (MVP)

Модуль обрабатывает чеки PNG и PDF: извлекает текст (встроенный слой PDF или OCR), с помощью LLM
выделяет чеки, сохраняет результат в SQLite и строит отчёты за период **по дате покупки**
без чтения почты и без повторного вызова AI.

Это локальный MVP. Веб-интерфейса, очередей задач, Docker и векторной базы нет.

### Установка OCR (Tesseract, внешняя системная зависимость)

Python-пакеты `pytesseract`, `pypdfium2`, `pypdf` и `pillow` ставятся через `pyproject.toml`.
Tesseract ставится отдельно. **Не запускайте установку без подтверждения** — это системный пакет:

```bash
brew install tesseract tesseract-lang
tesseract --list-langs     # должны быть rus и eng
```

Без Tesseract приложение выводит `OCR_UNAVAILABLE` и не подставляет результат.
Текстовые PDF с встроенным слоем обрабатываются без OCR.

### Команды

```bash
# Один локальный файл, только локальное извлечение текста (LLM не вызывается)
.venv/bin/python -m mail_assistant receipt extract samples/synthetic_receipt.pdf

# То же, но с распознанным текстом (явный флаг отладки)
.venv/bin/python -m mail_assistant receipt extract samples/synthetic_receipt.pdf --show-text

# С облачным AI (нужны LLM_*-настройки и LLM_EMAIL_USE_CONFIRMED=true; один платный запрос)
.venv/bin/python -m mail_assistant receipt extract ./чек.pdf --allow-cloud --model deepseek-v4.1-flash

.venv/bin/python -m mail_assistant receipt list
.venv/bin/python -m mail_assistant receipt show 1            # --text покажет текст документа
.venv/bin/python -m mail_assistant receipt review            # на проверку и подозрения на дубли
.venv/bin/python -m mail_assistant receipt edit 1 --amount 950.00 --category services
.venv/bin/python -m mail_assistant receipt confirm 1
.venv/bin/python -m mail_assistant receipt reject 1

.venv/bin/python -m mail_assistant report --from 2026-10-01 --to 2026-10-31
.venv/bin/python -m mail_assistant report --from 2026-10-01 --to 2026-10-31 --csv exports/oct.csv
```

Без `--allow-cloud` выполняется только локальное извлечение: LLM не вызывается, расход не создаётся.

### Синхронизация вложений из почты

```bash
# Сначала узнайте идентификатор папки (ни папка, ни UID не выбираются по догадке)
.venv/bin/python -m mail_assistant mail folders

# Dry-run: только UID и размеры писем; вложения не загружаются, LLM не вызывается
.venv/bin/python -m mail_assistant sync --mailbox "INBOX/Receipts" \
    --received-from 2026-10-01 --received-to 2026-10-31 --max-messages 20 --dry-run

# Реальный запуск: явный --allow-cloud, ограничение партии и числа LLM-запросов
.venv/bin/python -m mail_assistant sync --mailbox "INBOX/Receipts" \
    --received-from 2026-10-01 --received-to 2026-10-31 --max-messages 20 \
    --allow-cloud --max-llm-requests 5
```

Даты `sync` (`--received-*`) относятся к **получению письма** (IMAP `SINCE/BEFORE`).
Даты `report` (`--from/--to`) относятся к **дате покупки** из чека. Это разные даты:
письмо с чеком от 30 сентября может прийти 1 октября, и тогда оно попадёт в `sync` за октябрь,
но в `report` за октябрь попадёт только если покупка была в октябре.

Sync работает в режиме только чтения: `SELECT readonly=True`, `BODY.PEEK`, без `STORE`, `MOVE`,
`EXPUNGE`, `APPEND`. Письма не помечаются прочитанными, не перемещаются и не отправляются.
Вложения PNG и PDF определяются по содержимому, а не по имени. Имена вложений не используются как пути файлов.

### Что сохраняется и как

- **База:** `data/receipts.sqlite3` (по умолчанию; путь задаётся `RECEIPTS_DB_PATH`). Каталог `data/`
  создаётся с правами 700, файл — 600. SQLite по умолчанию **не зашифрована**.
- **Почта:** для сообщения хранится учётная запись, папка, `UIDVALIDITY` и UID. UID без папки и
  `UIDVALIDITY` не используется. Пароли и ключи в БД не сохраняются (проверяется тестом).
- **Документ:** SHA-256 исходных байтов, MIME по содержимому, размер, статус, код ошибки, извлечённый текст,
  версии извлечения и промпта/схемы, модель и usage, попытки обработки.
- **Чеки:** магазин, ИНН (если указан в тексте), дата и время покупки, валюта, сумма (целое число
  минорных единиц и текстовый вид), тип операции, категория, номер чека, фискальный ID, цитаты (evidence),
  предупреждения, статус проверки и история ручных исправлений.
- **Оригиналы** по умолчанию **не хранятся**. Включение `RECEIPT_STORE_ORIGINALS=true` сохраняет файлы
  в `RECEIPT_ORIGINALS_DIR` с правами 600 и именем по SHA-256. Включайте только если это необходимо:
  оригиналы содержат персональные данные.
- **Последствия отсутствия оригиналов:** `reprocess` требует исходного файла (его можно взять из почты заново),
  но обычный повтор без `--reprocess` использует сохранённый текст и не требует OCR.

### Статусы

- Обработка документа: `pending`, `text_extracted`, `ai_done`, `failed`, с кодом ошибки.
- Проверка записи: `extracted` (все поля найдены, цитаты подтверждены, предупреждений нет), `needs_review`
  (есть пропуски, сомнения или предупреждения), `confirmed` (подтверждена человеком), `rejected` (отклонена).
- Автоматического подтверждения нет. Запись с пустым магазином, датой, суммой, валютой или
  неизвестным типом операции подтвердить нельзя.
- Неполный текст (OCR обрезан или текст больше `LLM_MAX_INPUT_CHARS`) отмечается в записи и сохраняется
  при подтверждении (`confirmed_with_partial_text`).

### Проверки и защита

- **Суммы:** только `Decimal`. В базе — целые копейки, сумма в отчёте считается целыми числами.
  Float нигде не используется. Одна валюта — одна строка отчёта, конвертации нет.
- **Итог:** модель выбирает итог с цитатой. Код проверяет, что цитата есть в тексте, и эвристикой
  сравнивает сумму со строкой «ИТОГО / ВСЕГО / К ОПЛАТЕ». Если сумма совпадает со строкой НДС, скидки,
  сдачи или внесённой суммы, запись отправляется на проверку. Эвристика не гарантирует правильность.
- **Несколько чеков в одном документе:** все записи получают статус проверки, итоги проверяются вручную.
- **Дубли:** один SHA-256 — одна обработка, даже если вложение пришло в нескольких письмах
  (сохраняются все источники). Совпадение магазина, даты, суммы и валюты только помечается
  как подозрение (`receipt review`). Ничего не удаляется автоматически.
- **Повторный AI:** `--reprocess` предупреждает о платном запросе и создаёт новую версию результата.
  Подтверждённые и исправленные вручную записи не заменяются: новая версия сохраняется как неактуальная.
- **Неопределённые ошибки:** таймаут, сеть и HTTP 5xx после платного запроса помечаются `LLM_UNCERTAIN`
  и не повторяются автоматически. Повтор только через `--reprocess`.
- **Лимиты:** `RECEIPT_MAX_BYTES`, `RECEIPT_MAX_PAGES`, `RECEIPT_MAX_PIXELS`, `RECEIPT_OCR_TIMEOUT_SECONDS`,
  `LLM_MAX_INPUT_CHARS`. Защита Pillow от decompression bomb не отключается. Зашифрованные PDF не расшифровываются.
- **Облако:** текст чека передаётся в LLM только при `--allow-cloud` и `LLM_EMAIL_USE_CONFIRMED=true`.
  Передаётся только текст документа (без переписки, заголовков и вложений). Текст считается недоверенным,
  у модели нет инструментов. **Анонимизации чеков не гарантируется:** названия магазинов, ИНН и номера
  могут остаться в тексте.

### Отчёт и CSV

- `report` читает только SQLite: без IMAP, без LLM и без ключей.
- В основной итог входят только `confirmed` записи, актуальные (`is_current`), с датой покупки в периоде.
  Границы периода включительны.
- Выводятся расходы, возвраты, чистый итог, число чеков и число записей на проверку (с датой в периоде
  и без даты) отдельно по каждой валюте.
- CSV защищён от formula injection: значения, начинающиеся с `= + - @` и табуляции/возврата каретки,
  получают префикс апострофа. Существующий файл не перезаписывается без `--force`. Права 600.

### Тесты

```bash
.venv/bin/python -m pytest
```

Тесты используют синтетические PDF и PNG (генерируются кодом) и mock LLM. Реальные чеки в репозитории не хранятся.
Проверяются: текстовый PDF, скан, смешанный PDF, отсутствие OCR, повреждённые и зашифрованные файлы,

CSV-защиту и dry-run sync без LLM.

### Интерфейс (Streamlit, только localhost)

```bash
cd <путь-к-проекту>
.venv/bin/python -m streamlit run mail_assistant/web.py --server.address 127.0.0.1 --server.port 8501
```

Открыть http://127.0.0.1:8501. Все действия выполняются только кнопками: перерисовка страницы не
запускает импорт и не обращается к LLM или почте.

- **Почта:** «Загрузить список папок» (IMAP LIST), выбор папки, период получения, тип вложений
  (PNG/PDF), лимит писем и новых документов, кнопка «Загрузить чеки». Только чтение.
- **Свои файлы:** загрузка PNG/PDF и «Обработать загруженные».
- **AI:** выбор модели из списка совместимых с Chat Completions и «Распознать новые». Кнопка
  неактивна, пока облако отключено (причина выводится на экране). Повтор после неопределённого
  запроса (таймаут, сеть, 5xx) выполняется только явно.
- **Покупки:** таблица записей, исходный чек (если сохранён), цитаты, предупреждения, исправление
  магазина, даты, времени, суммы, валюты, категории и операции, подтверждение и отклонение.
- **Отчёт:** период по дате покупки, отдельно по каждой валюте: расходы, возвраты, чистый итог,
  суммы по магазинам и категориям. Неподтверждённые записи показаны отдельно и в итог не входят.
  CSV скачивается из памяти браузера.

Исходные чеки при импорте из почты и загрузке файлов сохраняются в `data/originals/` (права 600).
Каталог `data/` исключён из Git.

### Облачный AI и условия провайдера

- **Основание для отправки чеков в облачный API:** ваша отметка `LLM_EMAIL_USE_CONFIRMED=true` и ваше
  подтверждение допустимости сценария. Письменного подтверждения OpenCode Go в проекте **нет**.
  Проверенные условия (`opencode.ai/docs/go`) не содержат прямого запрета. Они описывают сервис как
  предназначенный в первую очередь для coding-агентов и требуют «typical coding agent traffic».
  Это не интерпретируется как запрет. Константа `OPENCODE_GO_RECEIPTS_CONFIRMED` в
  `mail_assistant/config.py` переключает облачную отправку чеков целиком.
- Локальные модели, Ollama и альтернативные провайдеры в проекте не используются.
- **Бюджет этапа:** до 15 LLM-запросов всего (включая повторы), не более 2 на документ (один повтор
  только при `finish_reason=length` и с бюджетом вывода 4096), без автоповтора после таймаута или
  сетевой ошибки с неизвестным исходом.
- Для рассуждающих моделей бюджет вывода может полностью уйти на внутреннее рассуждение. Диагностика
  попытки (`processing_attempts.diagnostics_json`) хранит только метаданные: `finish_reason`, тип
  `content`, наличие `reasoning`, `usage`, пути полей схемы. Текст ответа и рассуждений не хранится.
- Модели из списка интерфейса взяты из документации OpenCode Go, а не запрошены у сервера. Доступность
  каждой модели проверяется фактическим вызовом.

### Что не доказано

- Качество распознавания и корректность извлечённых полей на реальных чеках: сверяйте в таблице и по
  цитатам перед подтверждением.
- Записи с предупреждениями («не оплачен», «валюта не найдена», неполный текст) не подтверждаются
  автоматически.
- Подозрения на дубли (одинаковые магазин, дата, сумма и валюта в разных документах) не удаляются.
- Tesseract проверен реально (rus+eng). Качество OCR зависит от снимка: повторно проверяйте плохие фото.
